# serialize.goose read-path security audit — 2026-11-05

Scope: the read path of the serialize bit-packing runtime at base
`af700c3d96ee19f8671d2e51729223db97f46f22` (branch `sprint/serialize-audit`).
The generated code of the schema compiler calls this runtime on bytes from the
network, so its read path is the floor every schema-generated reader stands on.

This is a report-only audit: suspected issues are reported, no reproductions, no
hostile-input tests, no fuzz corpora or proof inputs. Writers are examined only
where the read path trusts something a writer produced. The card's STEP 4 fuzz
extension is superseded by the coordinator note of 2026-11-05: no fuzz corpus
was extended on this card; the existing `make fuzz` differential was run
unchanged as a gate only.

## Post-failure observable state

What a caller can observe after a refused read. In every row the latch is set
(first reason wins) and every later read refuses, so no row lets a caller resume
a failed stream; the differences below are observable only through
`serialize_bits_processed` / `serialize_bits_remaining` and the destination.

| refusal site | cursor (`bits_read`) after refusal | destination after refusal |
|---|---|---|
| gate refusals: `serialize_read_check` past-end, declaration checks before any bit moves (bad ranged/fixed range, bad compressed-float declaration, string capacity, `serialize_read_length` bad `buffer_size`) | unmoved | untouched |
| value refusals after the field was read: ranged offset past the span (`serialize_int`, `serialize_int64`, `serialize_int128`, `serialize_read_length`), `int_relative` reconstruction / canonical checks, compressed-float integer past max or non-finite decode, `float` / `double` non-finite pattern | advanced past the refused field | untouched (the assignment is after the check) |
| `fixed_read_core` offset past the span | **rewound** to the field start (`s.bits_read = start`, src/serialize_fixed.goose:179) — the one read that rewinds | untouched |
| `serialize_string` payload refusals (`past_end` on claimed length, `embedded_nul`, `invalid_utf8`) | left at the payload start (length and align consumed; payload bits are added only on success, src/serialize_bytes.goose:188) | untouched (`clear` / fill only after both payload scans pass) |
| `serialize_align` / `serialize_end` nonzero padding | advanced past the padding bits that were read | — (no destination) |
| `serialize_end` trailing data | unmoved | — |
| `serialize_object` callback refusal | wherever the nested reads left it | whatever the nested reads assigned before refusing; the object latches `rejected` (or keeps the inner reason) |

The cursor divergence (advance vs rewind vs payload-start) is finding
sra-goose-6.

## Findings

Every finding below is a report-only observation; none is fixed on this card.
Severities are calibrated against the actual effect on a reader that consumes
network bytes. There are no critical, high or medium findings at this base:
every refusal is a value, every read consumes only what its gate admitted, and
no wire byte can force an allocation beyond the packet's own size or a trap
under `--debug`. Findings 1–5 are accepted observations; findings 6–8 are OPEN.

### sra-goose-1 — window load and cross-word tail read are bounded only by the slack contract (info, accepted)

- file:line: src/serialize_bitpacker.goose:29-40 (window), :82 (`window`),
  :93 (`s.data[byte_index + 8]`), and the contract's enforcement at
  src/serialize_stream.goose:89-93 and :100-106.
- what attacker input does there: a read positioned at the last byte of the
  message (`byte_index = bytes - 1`) makes the packer load an 8-byte window
  `data[base..base+8]` and, on a value that crosses the word boundary, the next
  byte `data[byte_index + 8]`. Those accesses are inside `data` solely because
  the two initializers refuse any buffer that is not at least `bytes + 8` bytes.
- severity: info (no exploitable effect while the init invariant holds; it is
  the single point that must never be loosened).
- reduction: none required. The invariant is fail-closed at init; any future
  change to the initializers must keep `data.len >= bytes + 8` (and the padded
  form's `destination.len >= data.len + 8`) or add a tail branch to
  `serialize_packer_read`. Do not relax it on the hot path (IMPLEMENTING.md,
  the buffer contract).
- pin: `make witnesses` row `read-init-misuse-refused` (red on
  `TestU7ReadMissingSlackRefuses`), `TestBitpackerReadSlackMissingRefuses`,
  and the vendored past-end vectors (`bits-refuse-past-end-*`,
  `uint128-refuse-past-end-*`).

### sra-goose-2 — the read path computes in unsigned / `as!` arithmetic so no wire byte can trap under `--debug` (info, accepted)

- file:line: src/serialize_int.goose:46-51 and :78-83 (offset subtraction in
  `u32`/`u64`), src/serialize_int.goose:120-175 (`int_relative` reconstruction
  in `u32`), src/serialize_fixed.goose:166-184 (128-bit offset compare and the
  `s.bits_read = start` rewind), src/serialize_bitpacker.goose:78-96 (masked
  shifts guarded for 0 and full width).
- what attacker input does there: all-ones offsets, offsets one past the span,
  an `int_relative` bounded tier that would carry `previous` above `2^31-1`,
  and 64-bit splits — none of these can make Goose's checked `as` or overflow
  checks abort, because the arithmetic is unsigned or `as!` (DESIGN.md (c),
  (e); STANDARD.md, Reader Obligations; IMPLEMENTING.md U7).
- severity: info (the property is the point of the design; confirmed, not
  at risk).
- reduction: none. Preserve the unsigned-domain rule when the read path is
  touched (U7: a reader never traps; a refusal is a value).
- pin: `make witnesses` rows `int-relative-read-previous-in-domain`,
  `float-read-destination-unwritten`, `compressed-float-destination-unwritten`;
  conformance vectors `int-negative-min-refuse-offset-all-ones`,
  `int128-128-bit-span-refuse-offset-one-past-the-span`,
  `fixed-q64-64-refuse-offset-all-ones`, `absolute-refuse-all-bits-set`.

### sra-goose-3 — a hostile string length can grow a destination only to the packet's own size, never to `buffer_size` (low, accepted)

- file:line: src/serialize_bytes.goose:159-190; the claimed length is bound by
  `buffer_size - 1` (declaration, src/serialize_bytes.goose:40-51) and, before
  any `value.push`, by `length <= serialize_bits_remaining(s) / 8`
  (src/serialize_bytes.goose:177).
- what attacker input does there: a length field of all ones under a large
  `buffer_size` (e.g. `2^20`) claims a huge payload; the stream check refuses
  it `past_end` before the builder is cleared or grown, so the growable builder
  is never sized by the wire beyond the bytes actually in the packet.
- severity: low (a residual memory bound is present and correct; no unbounded
  allocation).
- reduction: none required. Do not remove the `bits_remaining / 8` gate (the
  division, not `length * 8`, is deliberate: `length * 8` could wrap for a huge
  `buffer_size`, the division cannot).
- pin: `test/strings/strings_test.goose:458`
  `TestSerializeStringClaimedLengthCheckedFirst` (the PORT-BRIEF allocate-
  before-check vector), and `make witnesses` row
  `string-length-checked-before-payload`.

### sra-goose-4 — the precomputed compressed-float form does not validate `min`, by the U16 list (info, accepted)

- file:line: src/serialize_compressed_float.goose:35-38 (`cf_precomputed_ok`
  checks `max_integer_value`, `bits`, `delta` but not `min`) and :124-144
  (decode refuses a non-finite result as `non_finite_float`).
- what attacker input does there: a caller that passes a non-finite `min` with
  otherwise-valid precomputed constants gets a refusal only at decode time
  (`non_finite_float`), not the bad-declaration `value_out_of_range` the
  non-precomputed form gives. The wire cannot influence `min`, and the outcome
  is still a refusal, so there is no read-path exploit; it is the reference's
  documented precomputed-check list (IMPLEMENTING.md U16), reproduced exactly.
- severity: info.
- reduction: none on this card. If a later card wants the precomputed form to
  fail earlier, add `cf_finite(min)` to `cf_precomputed_ok`; that is a
  behaviour change outside the reference's U16 list, so it belongs in a
  schema-level ruling, not here.
- pin: `test/uniform/uniform_test.goose:324`
  `TestU16ReadPrecomputedBadConstantsRefuses`.

### sra-goose-5 — the slack contract makes the window read a named residual, documented not fixed (info, accepted)

- file:line: src/serialize_bitpacker.goose:30 and :82 (the `assert` that feeds
  Goose's bounds analysis) with the residual named in DESIGN.md (d).
- what attacker input does there: none directly — the `assert(base + 7 <
  data.len)` is provably true for every position the gate admits, given the
  init-enforced slack, so Goose's checked indexing cannot be reached by the
  wire. It is a compile-time residual (Goose elides only some index checks),
  not a runtime refusal.
- severity: info.
- reduction: none; keep the `assert` (it is what lets the bounds analysis fold
  the window stores/loads).
- pin: `make fuzz` (differential against serialize.c) and `make test`.

### sra-goose-6 — post-failure cursor position diverges by family (info, OPEN)

- file:line: src/serialize_fixed.goose:179 (rewind) against
  src/serialize_int.goose:48-49, src/serialize_int128.goose:168-169,
  src/serialize_float.goose:60, src/serialize_compressed_float.goose:129-140
  (advance, no rewind) and src/serialize_bytes.goose:177-188 (payload start).
  Full table under "Post-failure observable state" above.
- what attacker input does there: any refused field leaves the latch set, so no
  later read can consume bytes at the divergent position; the divergence is
  observable only through the accounting accessors on an already-dead stream.
- severity: info (no exploitable effect while the latch is terminal, which
  `serialize_read_check` and every family's latch-first guard enforce).
- reduction: none required for safety. If a future card wants one rule, state
  it in STANDARD.md / IMPLEMENTING.md first (the reference's behaviour is the
  contract) and align the families to it; do not improvise per-family.
- status: OPEN (documented divergence, accepted risk none; left open so the
  contract question is not silently settled here).

### sra-goose-7 — `serialize_string` read computes `buffer_size - 1` before the `buffer_size >= 1` guard (low, OPEN)

- file:line: src/serialize_bytes.goose:164 (the capacity guard's
  `buffer_size - 1`) runs before `serialize_read_length`'s own
  `buffer_size >= 1` refusal at src/serialize_bytes.goose:41.
- what attacker input does there: none — `buffer_size` is the caller's
  declaration, never a wire value. For every `buffer_size` except the single
  value `i64` minimum, the subtraction cannot overflow and a bad declaration
  is refused `value_out_of_range` by `serialize_read_length` before any payload
  bit moves. At exactly the minimum, the subtraction itself is the first
  operation, so a checked (`--debug`) build would trap where U7 / U16 promise
  a reader refuses and never traps.
- severity: low (caller-declaration edge only; no wire reach, no effect for
  any other value).
- reduction: guard `buffer_size >= 1` at the top of the read overload of
  `serialize_string`, before the capacity subtraction, refusing
  `value_out_of_range` — one compare, matching `serialize_read_length`. That
  is a read-path change, so under this card's gate it ships only with fleet
  before/after numbers; none were run (no bench slot on this machine), so the
  fix stays open here rather than landing unmeasured.
- status: OPEN (fix specified, not landed; no pin added under report-only
  scope).

### sra-goose-8 — byte-count multiplications are bounded by caller-sized slices, not the wire (info, OPEN)

- file:line: src/serialize_stream.goose:93 and :106 (`bytes * 8`,
  `data.len * 8` at init), src/serialize_bytes.goose:112 (`data.len * 8` for a
  `serialize_bytes` destination).
- what attacker input does there: none directly. Each count is a caller slice
  length or a byte count already bounded by one (`bytes <= data.len - 8` at
  src/serialize_stream.goose:90), so overflowing `* 8` would need a slice
  within a factor of eight of the `i64` maximum — not allocatable, and never
  chosen by wire bytes. The one wire-sized multiplication, a string's
  `length * 8`, is deliberately avoided (sra-goose-3).
- severity: info.
- reduction: none. Keep the division form in `serialize_string`; do not
  introduce a `length * 8` gate anywhere a wire value sizes the count.
- status: OPEN (recorded bound; no change proposed).

## Not in scope / not applicable

- **Stack and recursion.** `serialize_object` is recursive, but the nesting is
  the schema's generated code, never the wire's: no byte in a packet can grow
  the call depth, so stack exhaustion is not reachable from untrusted input.
  Likewise the read side holds no cross-call scratch word — `serialize_packer_read`
  loads a fresh 8-byte window on every call — so there is no reader state a
  hostile bit position can corrupt across reads. The only read-side state is
  the cursor, the latch, and the caller's destination, each gated on the way in
  and untouched (or latched) on the way out of a refusal (DESIGN.md (d), (e)).
- **Allocation sized by input.** A `serialize_bytes` read's count is the
  caller's destination length (the schema's field size), not a wire field, so
  `data.len * 8` in its gate cannot be driven upward by hostile bytes; the only
  wire-driven length is a string's, and that is bound to the packet's own size
  before any grow (sra-goose-3). No read allocates, grows or recurses by a
  quantity the wire alone can choose.
- **JSON parsing** (depth, length, numbers, duplicate keys, escapes): this
  runtime carries no JSON parser. The format is not self-describing; a stream
  is meaningless without the exact sequence of calls (STANDARD.md, Compatibility
  Notes). Nothing to audit here.
- **Strict-only / tolerant-path work "in flight elsewhere"**: the strict-only
  work named in the card's brief is not on this base; the read path here is
  already strict (no repair, no clamp on the read side: an out-of-range
  compressed integer is refused, a non-finite decode is refused, the
  compressed-float read has no clamp). Nothing was made tolerant.

## Verdict

The read path is bounded at every entry point. No critical, high or medium
finding; eight info/low findings, of which 1–5 are accepted observations and
6–8 are OPEN (6: documented post-failure cursor divergence; 7: one
caller-declaration subtraction ahead of its guard, fix specified but held for
fleet numbers; 8: recorded caller-sized multiplication bound). No fix was made
on this card (report-only scope): no new tests, no fuzz corpora, no proof
inputs, no hostile-input reproductions. Continuation 2026-11-07 re-ran all
four gates locally with the same counts (`ok 7 test directories`,
`ok 58 witnesses`, `ok 19 controls`, fuzz 2000 programs / 486 mutants with the
same refusal-by-reason counts); the pinned Linux toolchain archive was not
fetched on this machine, so those runs used the locally installed Goose
runtime and are labelled as such in RESULT.md.
