# serialize.goose read-path security audit — 2026-11-05

Scope: the read path of the serialize bit-packing runtime at base
`af700c3d96ee19f8671d2e51729223db97f46f22` (branch `sprint/serialize-audit`).
The generated code of the schema compiler calls this runtime on bytes from the
network, so its read path is the floor every schema-generated reader stands on.

This is a report-only audit: suspected issues are reported, no reproductions, no
hostile-input tests, no fuzz corpora or proof inputs. Writers are examined only
where the read path trusts something a writer produced.

## Findings

Every finding below is a report-only observation; none is fixed on this card.
Severities are calibrated against the actual effect on a reader that consumes
network bytes. There are no open critical, high or medium findings at this base:
every refusal is a value, every read consumes only what its gate admitted, and
no wire byte can force an allocation beyond the packet's own size or a trap
under `--debug`.

### sra-goose-1 — window load and cross-word tail read are bounded only by the slack contract (info, accepted)

- file:line: src/serialize_bitpacker.goose:29-40 (window), :82 (`window`),
  :93 (`s.data[byte_index + 8]`), and the contract's enforcement at
  src/serialize_stream.goose:89-93 and :100-106.
- what attacker input does there: a read positioned at the last byte of the
  message (`byte_index = bytes - 1`) makes the packer load an 8-byte window
  `data[base..base+8]` and, on a value that crosses the word boundary, the next
  byte `data[byte_index + 8]`. Those accesses are inside `data` solely because
  the two initializers refuse any buffer that is not at least `bytes + 8` bytes.
- severity: info (no exploitable effect while the init invariant holds; it is
  the single point that must never be loosened).
- reduction: none required. The invariant is fail-closed at init; any future
  change to the initializers must keep `data.len >= bytes + 8` (and the padded
  form's `destination.len >= data.len + 8`) or add a tail branch to
  `serialize_packer_read`. Do not relax it on the hot path (IMPLEMENTING.md,
  the buffer contract).
- pin: `make witnesses` row `read-init-misuse-refused` (red on
  `TestU7ReadMissingSlackRefuses`), `TestBitpackerReadSlackMissingRefuses`,
  and the vendored past-end vectors (`bits-refuse-past-end-*`,
  `uint128-refuse-past-end-*`).

### sra-goose-2 — the read path computes in unsigned / `as!` arithmetic so no wire byte can trap under `--debug` (info, accepted)

- file:line: src/serialize_int.goose:46-51 and :78-83 (offset subtraction in
  `u32`/`u64`), src/serialize_int.goose:120-175 (`int_relative` reconstruction
  in `u32`), src/serialize_fixed.goose:166-184 (128-bit offset compare and the
  `s.bits_read = start` rewind), src/serialize_bitpacker.goose:78-96 (masked
  shifts guarded for 0 and full width).
- what attacker input does there: all-ones offsets, offsets one past the span,
  an `int_relative` bounded tier that would carry `previous` above `2^31-1`,
  and 64-bit splits — none of these can make Goose's checked `as` or overflow
  checks abort, because the arithmetic is unsigned or `as!` (DESIGN.md (c),
  (e); STANDARD.md, Reader Obligations; IMPLEMENTING.md U7).
- severity: info (the property is the point of the design; confirmed, not
  at risk).
- reduction: none. Preserve the unsigned-domain rule when the read path is
  touched (U7: a reader never traps; a refusal is a value).
- pin: `make witnesses` rows `int-relative-read-previous-in-domain`,
  `float-read-destination-unwritten`, `compressed-float-destination-unwritten`;
  conformance vectors `int-negative-min-refuse-offset-all-ones`,
  `int128-128-bit-span-refuse-offset-one-past-the-span`,
  `fixed-q64-64-refuse-offset-all-ones`, `absolute-refuse-all-bits-set`.

### sra-goose-3 — a hostile string length can grow a destination only to the packet's own size, never to `buffer_size` (low, accepted)

- file:line: src/serialize_bytes.goose:159-190; the claimed length is bound by
  `buffer_size - 1` (declaration, src/serialize_bytes.goose:40-51) and, before
  any `value.push`, by `length <= serialize_bits_remaining(s) / 8`
  (src/serialize_bytes.goose:177).
- what attacker input does there: a length field of all ones under a large
  `buffer_size` (e.g. `2^20`) claims a huge payload; the stream check refuses
  it `past_end` before the builder is cleared or grown, so the growable builder
  is never sized by the wire beyond the bytes actually in the packet.
- severity: low (a residual memory bound is present and correct; no unbounded
  allocation).
- reduction: none required. Do not remove the `bits_remaining / 8` gate (the
  division, not `length * 8`, is deliberate: `length * 8` could wrap for a huge
  `buffer_size`, the division cannot).
- pin: `test/strings/strings_test.goose:458`
  `TestSerializeStringClaimedLengthCheckedFirst` (the PORT-BRIEF allocate-
  before-check vector), and `make witnesses` row
  `string-length-checked-before-payload`.

### sra-goose-4 — the precomputed compressed-float form does not validate `min`, by the U16 list (info, accepted)

- file:line: src/serialize_compressed_float.goose:35-38 (`cf_precomputed_ok`
  checks `max_integer_value`, `bits`, `delta` but not `min`) and :124-144
  (decode refuses a non-finite result as `non_finite_float`).
- what attacker input does there: a caller that passes a non-finite `min` with
  otherwise-valid precomputed constants gets a refusal only at decode time
  (`non_finite_float`), not the bad-declaration `value_out_of_range` the
  non-precomputed form gives. The wire cannot influence `min`, and the outcome
  is still a refusal, so there is no read-path exploit; it is the reference's
  documented precomputed-check list (IMPLEMENTING.md U16), reproduced exactly.
- severity: info.
- reduction: none on this card. If a later card wants the precomputed form to
  fail earlier, add `cf_finite(min)` to `cf_precomputed_ok`; that is a
  behaviour change outside the reference's U16 list, so it belongs in a
  schema-level ruling, not here.
- pin: `test/uniform/uniform_test.goose:324`
  `TestU16ReadPrecomputedBadConstantsRefuses`.

### sra-goose-5 — the slack contract makes the window read a named residual, documented not fixed (info, accepted)

- file:line: src/serialize_bitpacker.goose:30 and :82 (the `assert` that feeds
  Goose's bounds analysis) with the residual named in DESIGN.md (d).
- what attacker input does there: none directly — the `assert(base + 7 <
  data.len)` is provably true for every position the gate admits, given the
  init-enforced slack, so Goose's checked indexing cannot be reached by the
  wire. It is a compile-time residual (Goose elides only some index checks),
  not a runtime refusal.
- severity: info.
- reduction: none; keep the `assert` (it is what lets the bounds analysis fold
  the window stores/loads).
- pin: `make fuzz` (differential against serialize.c) and `make test`.

## Not in scope / not applicable

- **JSON parsing** (depth, length, numbers, duplicate keys, escapes): this
  runtime carries no JSON parser. The format is not self-describing; a stream
  is meaningless without the exact sequence of calls (STANDARD.md, Compatibility
  Notes). Nothing to audit here.
- **Strict-only / tolerant-path work "in flight elsewhere"**: the strict-only
  work named in the card's brief is not on this base; the read path here is
  already strict (no repair, no clamp on the read side: an out-of-range
  compressed integer is refused, a non-finite decode is refused, the
  compressed-float read has no clamp). Nothing was made tolerant.
